# QQ 安全守卫

为 AstrBot 的 OneBot QQ 机器人提供默认拒绝的工具权限、隐私脱敏、受限文件操作、会话隔离、持久化限额与 Bot 自卸载保护。

**Bot 无权关闭、卸载或替换安全插件；操作者仍可在本机 WebUI 手动关闭、重载、更新、卸载或停止 AstrBot。插件不会阻止人工管理，也不会卸载后自行恢复。**

## 安装

要求 Python 3.11+、AstrBot 4.29.1（当前限定 4.29.x，其他版本尚未验证）。不安装额外依赖，不上传审计或配置，不访问遥测服务器。

在插件管理中使用仓库地址安装：

```text
https://github.com/a691201388/astrbot_plugin_qq_security
```

也可将发布 ZIP 解压为 `data/plugins/astrbot_plugin_qq_security/`，然后在 WebUI 重载插件。市场提交、审核及实际可搜索状态分别以 AstrBot Cloud 的结果为准。

## 默认行为

| 场景 | 行为 |
| --- | --- |
| 白名单为空 | 所有 QQ 均无文件操作权限；不会从昵称、管理员角色或其他账号信息猜测白名单 |
| 普通 QQ / 群聊 | 可聊天、使用已支持的绘图和表情工具；不能读写本机文件或调用未知工具 |
| 白名单 QQ 私聊 | 可使用独立工作目录中的文本文件读、写、列表工具；不因此获得 AstrBot 管理员身份 |
| 所有 Bot 对话，包括 WebChat | 不开放任意 Shell、Python、浏览器控制、MCP、子代理跳转、定时任务和插件管理工具 |
| 插件关闭、卸载、替换、整体重载 | Bot 工具执行上下文拒绝触发安全插件的生命周期操作；人工 WebUI 操作保留 |
| 消息、图片或文档声称“我是管理员” | 不改变权限，只按平台提供的真实发送者 ID 判断 |

### 为什么不开放任意执行

同进程插件无法安全地一边允许模型执行任意代码，一边保证模型不能修改或删除插件。因此本插件主动移除所有通用执行入口，并只提供受限的数据文件工具。需要真实桌面控制、运行脚本或系统管理时，应另行部署由操作系统强制隔离的执行服务，不能把当前保护解释为任意主机执行的安全许可。

第三方插件仍以 AstrBot 进程权限运行。本插件不是防病毒软件或操作系统沙箱，无法隔离恶意同进程 Python 插件、外部原生 Agent、已被入侵的宿主机或拥有同等系统权限的其他程序。不要安装不可信插件。

## 配置

进入插件配置页：

- `computer_qq_whitelist`：允许文件操作的真实 QQ 号，字符串列表。默认空。仅 OneBot 私聊有效。
- `emergency_stop`：禁止后续工作目录操作；不回滚已完成操作，普通聊天与绘图继续。
- `sensitive_terms`：可在本机填写姓名、住址、单位位置或其他隐私词条。词条本身不会注入模型提示词；只做明确字符串匹配。
- `chat_messages_per_minute`：每个机器人账号下，每个真实 QQ 每分钟最多模型请求数，默认 10，跨群共用。
- `daily_image_limit`：每个 QQ 每个 UTC 自然日最多绘图请求数，默认 20。重启不清零，失败请求也计数，0 禁止绘图。
- `image_cooldown_seconds`：同一 QQ 绘图请求最小间隔，默认 60 秒。
- `image_concurrency`：全局绘图并发上限，默认 2；每个 QQ 同时最多一个。超限拒绝，不自动重放请求。

保存配置后按当前 AstrBot 提示重载使其生效。允许名单或急停状态会在工具实际执行时再次检查。首次启用会为 QQ 使用新的隔离会话命名空间；变更白名单身份也会切换命名空间，旧历史不删除、不合并。群成员之间、不同群之间、不同机器人账号之间均不共用该命名空间。保留原会话选中的配置文件、原生白名单及停用限制；原会话或新会话任一禁止聊天、模型调用或指定插件时，继续遵守该限制。

插件通过可恢复的运行时包装，将会话编号固定在活动事件登记之前，将图片检查放在原生唤醒、白名单检查之后、媒体预处理之前。无需修改 AstrBot 核心文件；人工停用或卸载会撤回这些包装。使用按配置文件启用插件列表时，必须包含本插件；否则拦截该配置文件下的后续处理，防止配置排除绕过。

## 受限工作目录

提供 `qq_guard_read`、`qq_guard_write`、`qq_guard_list` 三个工具，文件位于插件数据目录中按账号和发送者分隔的工作区。模型不能选择工作区根目录。

- 只接受相对路径和 `.txt`、`.md`、`.csv`、`.json`、`.yaml`、`.yml`、`.log` 数据文件。
- 每个文件最多 64 KiB，每个工作区最多列出和创建 200 个文件。
- 拒绝绝对路径、路径越界、设备文件、NTFS 数据流、符号链接、目录联接和多链接文件。
- 不提供删除、执行、插件配置编辑、文件外发或目录迁移工具；需要这些操作由操作者手动处理。
- 文件工具会再次校验 QQ 身份、私聊和急停状态，不能靠模型选择了工具就跳过检查。

## 绘图和表情

当前保留以下经过明确匹配的工具，其余插件工具默认隐藏：

- `astrbot_plugin_codex_provider` 的 `codex_generate_image`。
- `meme_manager` 的 `search_memes`。

`/codex_image 描述` 与自然语言绘图使用同一套持久化额度。QQ 图片引用仅接受官方 QQ 图片域名的 HTTPS 地址；本机路径、内网地址、非标准端口、用户信息伪装和任意外链不作为绘图引用。下载禁止重定向、拒绝解析到私有或特殊用途 IP，限制每张 12 MiB、2500 万像素、每条消息最多 4 张，并绑定到当前消息后才交给 AstrBot。消息处理结束或取消时清理下载文件。图片引用失败时应重新发送 QQ 图片，不通过解除安全限制来兼容。

当前仅开放文字、QQ 图片、引用、@ 和 QQ 原生表情输入；语音、视频、合并转发和文档附件暂时拦截，避免这些入口在其他插件处理前访问未经验证的资源。安全模式处理私聊及原生唤醒或命令命中的群消息；未唤醒的群消息不下载图片、不自动收集素材，也不占聊天额度。聊天频率仅在模型请求时计数，`/stop` 等保留控制命令不受该限额阻挡。

输出只接受受支持工具自有目录中的有效图片或受允许的 QQ 图片链接。普通文件、未知富媒体和其他本机图片会被拦截。文本及流式回复会经过脱敏，分段文本先合并再检查，避免将隐私词条拆成几段发出。

保留 `/help`、`/sid`、`/reset`、`/new`、`/stop`、`/qq_guard_status`。其他插件管理和会话配置命令不向 Bot 对话开放；已匹配命令的别名和不同唤醒前缀也会检查。可以在本机 WebUI 正常管理其他插件。

## 部署补充

这些设置属于 AstrBot / 操作系统配置，不由市场插件偷偷修改：

1. NapCat 和 AstrBot 同机部署时，把管理端及 OneBot 接口限制到 `127.0.0.1`，保留独立 Token 和强管理密码。
2. 将原生普通成员的文件访问设为禁止，执行代码与执行联网设为关闭。无需原生电脑工具时将 Computer Use 设为 `none`。
3. 使用 AstrBot 内置 Agent 执行器。ChatGPT Codex 桥接插件须使用 `transport`，关闭其本地原生工具；无法拦截的外部 Agent 会被阻止继续模型调用。
4. 保持群上下文共享、群历史工具和自动跨会话消息关闭。其他长期记忆插件也必须单独核对用户隔离。
5. 框架和其他插件日志由各自控制；本插件审计只保存不透明发送者标识、操作名、时间及结果，不记录消息正文或文件内容，最多保留 10,000 条。
6. 条件允许时，用独立标准系统账户、容器或虚拟机部署；不要给 Bot 挂载个人文档、浏览器资料、SSH / Codex 凭据或宿主机管理接口。

脱敏是补充防护，不能自动识别所有姓名、地理信息、编码变体、图片画面或照片元数据。不要把敏感内容作为普通素材上传；泄漏过的凭据应轮换。已发送 QQ 消息和既有外部备份不由本插件保证擦除。

## 开发验证

在安装 AstrBot 运行依赖的环境中：

```shell
python -m pip install pytest pytest-asyncio
python -m pytest -q
ruff check .
ruff format --check .
```

测试使用临时数据目录与合成消息，不登录 QQ、不发送真实 QQ 消息、不调用模型或绘图服务。覆盖真实 AstrBot 工具执行器、Bot / 人工生命周期区别、空白名单、群聊限制、同名伪装工具、路径越界、硬链接、流式分段脱敏、持久化额度及异常时拒绝继续处理。
