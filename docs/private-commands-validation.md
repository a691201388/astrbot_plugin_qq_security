2026-10-25。QQ 命令只在经过双重名单验证的管理员私聊中沿用原规则；
群内管理员、普通群友和非管理员私聊命中命令均静默停止。

## 检查结果

- 实际 AstrBot 4.29.1 唤醒和命令分发：内置帮助、插件命令、别名、命令组、
  正则命令、@ 唤醒和替代前缀均覆盖。缺参数、权限不足也不发送提示。
- 普通 `/你好`、编程讲解、自然语言绘图/搜图输入继续唤醒；引用中的命令
  不作为当前用户命令。管理员私聊保留原命令白名单及电脑工具授权边界。
- 输出检查覆盖直接发送、流式发送和模型静默标记；命令等待期间任一管理员
  名单撤销后，后续输出丢弃。撤销不会回滚此前已经发生的操作。
- 初始新增测试先观察到 30 项失败，修复后 36 项通过。独立只读审查发现两项
  Important 问题：多条件过滤误作 OR，以及等待后发送未复核权限。新增 7 项
  测试均先失败，修复后完整套件 **278 项通过**。两项原有弃用警告保留
  （audioop、register_star），Ruff 和 diff 检查通过。没有第二次审查。

## 实现取舍与限制

- 命令身份使用真实 OneBot 私聊及两个管理员名单，不依赖完整 Codex 开关。
  急停时仍可私聊查询帮助；电脑执行继续受急停约束。
- 全部插件命令都受限，因此群成员也不能自助使用“鱼聊忘记我”；删除请求
  需管理员通过私聊或本机处理，代价是失去直接自助入口。
- 自然语言命令咨询依赖模型指导和静默标记，六条样本不构成全面保证。
  硬性边界是注册命令入口及既有工具权限；不能宣称语义分类永不漏判。
- 预检遵守可静态检查的命令、正则、消息类型和平台条件的 AND 关系。
  不提前执行自定义过滤器；匹配命令时保守阻止，可能比插件自定义条件更严。
- RegexFilter 沿用 AstrBot 的命令分类；不能保证每个第三方正则入口语义上
  都是管理命令。已安装的记忆、表情管理、鱼聊、搜图和 Codex 命令使用
  标准命令注册入口。恶意同进程插件及绕过事件发送的原始 QQ API 不在保证内。
- 未验证真实 QQ 送达、热重载和部署兼容性。开发包不自动安装，当前运行
  实例保持 0.3.9；无新的群聊天采集、权限配置更改或市场发布。
